**Hiểu lazy loading qua một ví dụ**

`Role.UserRoles` là **navigation property**: thuộc tính giúp đi từ một role đến các bản ghi `UserRole` liên quan.

Khi bật lazy loading, bạn có thể viết:

```csharp
var role = await dbContext.Roles.FirstAsync();

// Nếu dữ liệu quan hệ chưa được tải,
// việc truy cập thuộc tính này có thể khiến EF chạy thêm SQL.
var userRoles = role.UserRoles;
```

EF thực hiện điều đó bằng cách tạo một lớp con đặc biệt, gọi là **proxy**, kế thừa `Role`. Proxy can thiệp vào getter của `UserRoles` để tải dữ liệu khi cần. [Tài liệu lazy loading](https://learn.microsoft.com/en-us/ef/core/querying/related-data/lazy).

Muốn lớp con ghi đè getter, property của lớp cha phải có `virtual`. Trong C#, `virtual` nghĩa là **cho phép lớp kế thừa thay đổi cách thực hiện property hoặc method bằng `override`**. [Tài liệu C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/virtual).

**Vì sao đang chạy migration lại gặp lỗi này?**

Migration cần tạo `DbContext` để đọc entity, quan hệ và cấu trúc bảng trước khi sinh migration. [Tài liệu design-time DbContext](https://learn.microsoft.com/en-us/ef/core/cli/dbcontext-creation).

Luồng của bạn đang dừng ở đây:

```text
Chạy migration
    → Tạo DbContext và dựng model
    → Kiểm tra điều kiện tạo proxy
    → Phát hiện Role.UserRoles thiếu virtual
    → Báo lỗi và dừng
```

Vì vậy, đoạn `Unable to create a DbContext` là thông báo tổng quát; phần chỉ rõ nguyên nhân là `Property 'Role.UserRoles' is not virtual`.

**Chỉ cần thêm `virtual` cho các navigation này.** Cấu hình hiện tại dùng `UseLazyLoadingProxies`; các property thông thường như `Name`, `UserName`, `UserId`, `RoleId` không cần đổi sang `virtual`. Thông báo lỗi nhắc thêm `UseChangeTrackingProxies` để mô tả yêu cầu của cả hai loại proxy.

**Một cách khác là tắt lazy loading**

Nếu muốn tự chỉ định khi nào tải dữ liệu liên quan, bạn có thể bỏ dòng bật proxy hoặc đổi thành:

```csharp
.UseLazyLoadingProxies(false)
```

Sau đó dùng `Include` khi cần:

```csharp
var role = await dbContext.Roles
    .Include(r => r.UserRoles)
    .ThenInclude(ur => ur.User)
    .FirstOrDefaultAsync(r => r.Id == roleId);
```

`Include` và `ThenInclude` yêu cầu EF tải các quan hệ được chỉ định trong truy vấn. [Tài liệu eager loading](https://learn.microsoft.com/en-us/ef/core/querying/related-data/eager).

Với cấu hình bạn đang giữ, **thêm `virtual` vào bốn navigation property là cách sửa trực tiếp nhất**. Tôi mới kiểm tra và giải thích, chưa chỉnh file.

**Với ASP.NET Core API chạy production, tôi khuyên mặc định tắt lazy loading và chủ động tải dữ liệu cần dùng.** Microsoft cũng khuyến nghị tránh lazy loading vì rất dễ phát sinh vấn đề **N+1 queries**. [Tài liệu EF Core](https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying#beware-of-lazy-loading).

Lazy loading vẫn có thể dùng trong production khi kiểm soát được truy vấn. Tuy nhiên, việc truy cập một property có thể âm thầm gọi database, khiến hiệu năng khó dự đoán.

**Ví dụ N+1 dễ hiểu**

Bạn tải 100 user, sau đó duyệt từng user để đọc `UserRoles`:

- Một câu SQL lấy danh sách user.
- Nếu quan hệ chưa được tải, mỗi user có thể phát sinh thêm một câu SQL lấy `UserRoles`.
- Tổng cộng có thể thành **101 câu SQL**.

Đó là vấn đề N+1. [Tài liệu lazy loading](https://learn.microsoft.com/en-us/ef/core/querying/related-data/lazy).

**Cách code khác nhau ở bước tải dữ liệu quan hệ**

Ví dụ dưới đây là truy vấn trong Infrastructure/repository.

Khi **dùng lazy loading**:

```csharp
var user = await dbContext.Users
    .FirstAsync(u => u.Id == userId, cancellationToken);

// Dòng này có thể phát sinh thêm SQL khi truy cập navigation.
var roleNames = user.UserRoles
    .Select(ur => ur.Role.Name)
    .ToList();
```

Khi **tắt lazy loading**, bạn chỉ rõ quan hệ cần tải:

```csharp
var user = await dbContext.Users
    .Include(u => u.UserRoles)
        .ThenInclude(ur => ur.Role)
    .FirstAsync(u => u.Id == userId, cancellationToken);

// Dùng dữ liệu quan hệ đã được tải.
var roleNames = user.UserRoles
    .Select(ur => ur.Role.Name)
    .ToList();
```

Ở đây:

- `Include(u => u.UserRoles)`: tải các bản ghi nối user với role.
- `ThenInclude(ur => ur.Role)`: tải thông tin role tương ứng.

Đây gọi là **eager loading**. [Tài liệu Include/ThenInclude](https://learn.microsoft.com/en-us/ef/core/querying/related-data/eager).

**Những phần code nào cần thay đổi?**

| Phần code | Khi tắt lazy loading |
|---|---|
| Cấu hình DbContext | Bỏ `.UseLazyLoadingProxies(true)` hoặc chuyển thành `false` |
| Navigation property | Có thể giữ property thông thường, không bắt buộc `virtual` |
| Truy vấn cần dữ liệu quan hệ | Thêm `Include`/`ThenInclude`, hoặc dùng `Select` |
| Truy vấn chỉ cần thông tin user | Không cần thêm `Include` |
| Thêm, sửa, xóa và `SaveChangesAsync` | Cơ chế vẫn như hiện tại |

Đặc biệt, **tắt lazy loading không có nghĩa là navigation luôn tự chứa đầy đủ dữ liệu**. Nếu chưa tải quan hệ, collection khởi tạo rỗng có thể vẫn rỗng dù database có bản ghi liên quan.

Trong INuStore hiện tại, `LoginAsync` chỉ tạo claims từ `Id`, `UserName`, `Email`, nên chưa cần tải `UserRoles`. Khi bạn bổ sung role vào token, repository mới cần tải thêm quan hệ đó.

Với API chỉ đọc và trả DTO, bạn cũng nên cân nhắc `Select` để lấy đúng các trường cần trả, thay vì tải cả entity graph. [Hướng dẫn truy vấn hiệu quả](https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying#project-only-properties-you-need).
