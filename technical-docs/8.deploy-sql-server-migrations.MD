# Tạo và cập nhật INuStoreDB bằng SQL script

Ví dụ này dùng SQL Server LocalDB và SQL Server Management Studio (SSMS). Bạn sẽ cấu hình API, tạo database rỗng, sinh file SQL từ các migration trong repo rồi chạy file để tạo bảng và thêm dữ liệu mặc định.

## Bước 1. Sửa cấu hình kết nối

Trong [appsettings.Development.json](../src/INuStore.API/appsettings.Development.json), thêm hoặc sửa mục `ConnectionStrings` bên dưới. Giữ các mục cấu hình khác trong file.

```json
{
  "ConnectionStrings": {
    "ConnectionStrings": "Server=(localdb)\\MSSQLLocalDB;Database=INuStoreDB;Integrated Security=True;TrustServerCertificate=True"
  }
}
```

`Server` là SQL Server instance và `Database` là tên database. `Integrated Security=True` dùng tài khoản Windows đang chạy API. Trong SSMS, kết nối tới `(localdb)\MSSQLLocalDB` bằng **Windows Authentication** với cùng tài khoản. Nếu đã đặt biến môi trường `ConnectionStrings__ConnectionStrings`, cập nhật giá trị đó vì nó ghi đè cấu hình trong file.

## Bước 2. Tạo database rỗng

Trong SSMS, mở **New Query** trên instance vừa kết nối và chạy:

```sql
USE [master];
GO

IF DB_ID(N'INuStoreDB') IS NULL
    CREATE DATABASE [INuStoreDB];
GO
```

Trong **Object Explorer**, làm mới mục **Databases** để thấy `INuStoreDB`.

## Bước 3. Tạo migration nếu model có thay đổi mới

Sau khi thêm `HasData` cho role, chạy lệnh sau từ thư mục chứa `INuStore.slnx` nếu migration `SeedRoles` chưa có trong repo.

```powershell
dotnet ef migrations add SeedRoles --project src/INuStore.Infrastructure --startup-project src/INuStore.API --context ApplicationDbContext -- --environment Development
```

Lệnh tạo file migration, file `.Designer.cs` và cập nhật model snapshot. Kiểm tra `Up` có `InsertData` cho năm role. INuStore đã có [20261113092252_SeedRoles.cs](../src/INuStore.Infrastructure/Migrations/20261113092252_SeedRoles.cs), nên với phiên bản hiện tại bạn có thể sang thẳng bước 4.

## Bước 4. Sinh file SQL từ migration

Mở PowerShell tại thư mục chứa `INuStore.slnx`. Kiểm tra `dotnet ef --version` và dùng phiên bản 10.0.x phù hợp với EF Core của dự án.

```powershell
New-Item -ItemType Directory -Path .\deployment\sql -Force | Out-Null

dotnet ef migrations script 0 --idempotent `
  --project src/INuStore.Infrastructure `
  --startup-project src/INuStore.API `
  --context ApplicationDbContext `
  --output .\deployment\sql\inustore-migrations.sql `
  -- --environment Development
```

`0` nghĩa là lấy từ migration đầu tiên. Lệnh ghi SQL đến migration mới nhất vào `deployment\sql\inustore-migrations.sql`. Đây là bước tạo file trên máy. Database chỉ thay đổi khi chạy file ở bước 5. Các migration hiện có đã bao gồm seed permission và năm role mặc định. [Microsoft Learn — Sinh SQL từ migration](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying#sql-scripts)

## Bước 5. Chạy file SQL để tạo bảng

1. Trong SSMS, mở file `deployment\sql\inustore-migrations.sql`.
2. Trên tab chứa file, kiểm tra đúng instance và chọn **INuStoreDB** trong danh sách database.
3. Bỏ chọn mọi đoạn văn bản, nhấn **F5** để chạy toàn bộ file rồi xem tab **Messages**. Nếu có lỗi, xử lý lỗi đầu tiên trước khi chạy lại.

## Bước 6. Kiểm tra kết quả

Mở query trên **INuStoreDB** và chạy:

```sql
SELECT DB_NAME() AS DatabaseName;
SELECT MigrationId FROM dbo.__EFMigrationsHistory ORDER BY MigrationId;
SELECT Id, Name FROM dbo.Roles ORDER BY Id;
```

Kết quả cần hiện `INuStoreDB`, lịch sử có migration `SeedRoles` và bảng `Roles` có `Admin`, `Manager`, `Staff`, `Customer`, `Shipper`. Khi chạy API với cấu hình Development, gọi `GET /health/ready` để kiểm tra API kết nối được database.

## Khi cần cập nhật database đã có

1. Nếu vừa sửa model và chưa có migration cho thay đổi đó, tạo migration trong PowerShell.

   ```powershell
   dotnet ef migrations add TenThayDoi `
     --project src/INuStore.Infrastructure `
     --startup-project src/INuStore.API `
     --context ApplicationDbContext `
     -- --environment Development
   ```

2. Sinh lại file theo bước 4 và duyệt SQL trước khi chạy. Nhờ `--idempotent`, script tra bảng `__EFMigrationsHistory` để bỏ qua migration đã áp dụng và chạy các migration còn thiếu.
3. Chạy file trên database hiện có theo bước 5, rồi kiểm tra lịch sử theo bước 6. Nếu cập nhật lên `SeedRoles`, kiểm tra trước các ID từ 1 đến 5 và tên role vì bản ghi trùng có thể làm lệnh chèn thất bại.

## Best practices cho production

Duyệt `Up`, SQL và tác động lên dữ liệu cũ trên staging trước khi triển khai. Giữ thay đổi model, migration, designer và snapshot trong cùng đợt review. Chuẩn bị backup có thể khôi phục khi migration chạm vào dữ liệu đang dùng.

### Xuất SQL theo phạm vi migration

Sinh SQL từ `0` nếu database chưa có migration. Với database đang chạy, đọc `__EFMigrationsHistory` rồi lấy migration cuối đã áp dụng làm mốc bắt đầu và migration muốn nâng tới làm mốc kết thúc. Ví dụ, database đã có `20261112082137_SeedPermissions` và cần thêm `SeedRoles`. Chạy PowerShell từ thư mục chứa `INuStore.slnx`.

```powershell
New-Item -ItemType Directory -Path .\deployment\sql -Force | Out-Null
$sqlDate = Get-Date -Format 'ddMMyyyy'
dotnet ef migrations script 20261112082137_SeedPermissions SeedRoles --idempotent --project src/INuStore.Infrastructure --startup-project src/INuStore.API --context ApplicationDbContext --output ".\deployment\sql\${sqlDate}_SeedRoles.sql" -- --environment Development
```

File theo mẫu `ddmmyyyy_<TênMigration>.sql`. Mở file để kiểm tra thao tác chèn role và ID migration trước khi chạy trên đúng database. `--idempotent` bỏ qua migration đã ghi trong lịch sử. Nếu `SeedRoles` còn thiếu trong lịch sử, kiểm tra các ID từ 1 đến 5 và tên role hiện có để tránh trùng khi chèn. Chạy SQL trong SSMS theo [Bước 5](#bước-5-chạy-file-sql-để-tạo-bảng) và kiểm tra dữ liệu seed từ `HasData` theo [Bước 6](#bước-6-kiểm-tra-kết-quả). [Microsoft Learn — Script theo phạm vi migration](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying#idempotent-sql-scripts)

File [13112026_SeedPermissions.sql](../deployment/sql/13112026_SeedPermissions.sql) là ví dụ xuất riêng migration seed permission. Database đích cần đã áp dụng đến `20261111165739_ProtectPermissionNamesAndAssignments` trước khi chạy file này.
