# Triển khai INuStoreDB bằng SQL script

Dùng quy trình này để tạo lại database đã xóa hoặc áp dụng migration mới qua SQL Server Management Studio (SSMS). Nếu cần lấy lại tài khoản và dữ liệu cũ, hãy khôi phục từ backup.

## 1. Sinh file SQL

Mở PowerShell tại thư mục chứa `INuStore.slnx`. Kiểm tra `dotnet ef --version` và dùng `dotnet-ef` cùng dòng 10.0 với EF Core của dự án. [Project Infrastructure](../src/INuStore.Infrastructure/INuStore.Infrastructure.csproj)

```powershell
New-Item -ItemType Directory -Path .\deployment\sql -Force | Out-Null

dotnet ef migrations script 0 --idempotent --project src/INuStore.Infrastructure --startup-project src/INuStore.API --context ApplicationDbContext --output .\deployment\sql\inustore-migrations.sql -- --environment Development
```

Lệnh ghi các migration từ đầu đến bản mới nhất vào `deployment\sql\inustore-migrations.sql`. Khi chạy file, `--idempotent` giúp bỏ qua migration đã có trong bảng `__EFMigrationsHistory` của database hiện tại. File sinh ra dùng được với nhiều tên database, nên EF không thêm `USE`. Nếu chạy file trong `master` bằng tài khoản có quyền tạo bảng, các bảng có thể được tạo trong `master`. [Microsoft Learn — Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying#idempotent-sql-scripts)

## 2. Tạo database nếu chưa có

Trong SSMS, kết nối đúng SQL Server instance mà API sẽ dùng. Với LocalDB, nhập `(localdb)\MSSQLLocalDB`, chọn **Windows Authentication** và dùng cùng tài khoản Windows chạy API. Connection string của API cần trỏ tới `Database=INuStoreDB` và dùng `Integrated Security=True`. Xóa `User Id` và `Password` khỏi connection string khi chuyển sang Windows Authentication. [Cấu hình DbContext](../src/INuStore.Infrastructure/DependencyInjection/Extensions/ServiceCollectionExtensions.cs) · [Microsoft Learn — LocalDB](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/sql-server-express-localdb)

Mở **New Query** trên đúng instance và chạy đoạn sau bằng tài khoản có quyền tạo database:

```sql
USE [master];
GO

IF DB_ID(N'INuStoreDB') IS NULL
    CREATE DATABASE [INuStoreDB];
GO
```

## 3. Chạy migration trong SSMS

1. Mở `deployment\sql\inustore-migrations.sql` bằng **File → Open → File**.
2. Trên chính tab chứa file, kiểm tra kết nối, chọn database **INuStoreDB** và bật **Query → SQLCMD Mode**.
3. Chèn đoạn sau vào đầu script. Thêm lại sau mỗi lần sinh file mới. `:ON ERROR EXIT` dừng script nếu `USE` thất bại. [Microsoft Learn — SQLCMD Mode trong SSMS](https://learn.microsoft.com/en-us/sql/ssms/scripting/edit-sqlcmd-scripts-with-query-editor)

   ```sql
   :ON ERROR EXIT
   USE [INuStoreDB];
   GO
   ```

4. Bỏ chọn mọi đoạn văn bản, nhấn **F5** để chạy toàn bộ file và xem tab **Messages**. Nếu có lỗi, kiểm tra lỗi đầu tiên trước khi chạy lại.

## 4. Kiểm tra migration và thêm role mặc định

Mở query mới trên cùng instance, chọn **INuStoreDB** rồi kiểm tra:

```sql
SELECT @@SERVERNAME AS ServerName, DB_NAME() AS DatabaseName;
SELECT [MigrationId] FROM [dbo].[__EFMigrationsHistory] ORDER BY [MigrationId];
```

Kết quả cần hiện `INuStoreDB` và migration mới nhất trong file SQL. Với file hiện tại, đó là `20261112082137_SeedPermissions`. Migration này thêm các permission mặc định. [SeedPermissions.cs](../src/INuStore.Infrastructure/Migrations/20261112082137_SeedPermissions.cs)

`builder.UseSeeding(...)` đăng ký một callback C#. Khi EF gọi callback, nó kiểm tra từng tên role, thêm các role còn thiếu rồi lưu bằng `context.SaveChanges()`. [Cấu hình UseSeeding](../src/INuStore.Infrastructure/DependencyInjection/Extensions/ServiceCollectionExtensions.cs)

- `Update-Database` và `dotnet ef database update` chạy callback kể cả khi database đã có đủ migration.
- EF cũng gọi callback qua `Database.Migrate()` hoặc `Database.EnsureCreated()` đồng bộ. API hiện tại không gọi các phương thức này lúc khởi động.
- Chạy script trong SSMS, khởi động API, gọi endpoint hoặc gọi `SaveChanges()` thông thường đều không kích hoạt callback. Vì vậy, nếu database vừa tạo và chỉ chạy file migration trong SSMS, năm role mặc định vẫn chưa được thêm. [Microsoft Learn — Data Seeding](https://learn.microsoft.com/en-us/ef/core/modeling/data-seeding)

Để thêm các role còn thiếu khi triển khai bằng SQL, chạy đoạn sau trên **INuStoreDB** sau khi migration thành công.

```sql
INSERT INTO [dbo].[Roles] ([Name], [Description])
SELECT [seed].[Name], [seed].[Description]
FROM (VALUES
    (N'Admin', N'Admin for the Store'),
    (N'Manager', N'Manager for the Store'),
    (N'Staff', N'Staff for the Store'),
    (N'Customer', N'Customer for the Store'),
    (N'Shipper', N'Shipper for the Store')
) AS [seed] ([Name], [Description])
WHERE NOT EXISTS (
    SELECT 1
    FROM [dbo].[Roles] AS [existing]
    WHERE [existing].[Name] = [seed].[Name]
);

SELECT [Name] FROM [dbo].[Roles] ORDER BY [Name];
```

Khởi động API và gọi `GET /health/ready`. Kết quả `200 Healthy` xác nhận API kết nối được SQL Server. Nếu API vẫn báo `Login failed for user 'sa'` khi dùng LocalDB, kiểm tra giá trị connection string thực tế, gồm biến môi trường `ConnectionStrings__ConnectionStrings` nếu được đặt. [Cấu hình health check](../src/INuStore.Infrastructure/DependencyInjection/Extensions/ServiceCollectionExtensions.cs)

## Best practices cho production

- Duyệt file SQL và chạy thử trên staging trước khi triển khai. Xác nhận đúng instance và database trên mỗi lần chạy.
- Chuẩn bị backup có thể khôi phục trước khi nâng cấp database có dữ liệu. Nếu script dừng giữa chừng, đối chiếu schema và `__EFMigrationsHistory` trước khi chạy lại. [Microsoft Learn — Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying)
