> Các đoạn code Streaming và SkipTransaction trong bài là ví dụ minh họa. API hiện tại của INuStore dùng POST /api/v1/files/buffered.

Đây là hai đoạn code khá phổ biến trong **ASP.NET Core Web API**, đặc biệt khi làm việc với **File Upload Streaming** và **Middleware xử lý Transaction**.

Mình sẽ giải thích từ cơ bản, theo góc nhìn của một Fresher, để bạn hiểu không chỉ code đang làm gì mà còn hiểu **tại sao cần dùng, ASP.NET Core xử lý như thế nào và khi nào nên áp dụng**.

Hai đoạn code này thuộc hai cơ chế khác nhau:

| Đoạn code                               | Cơ chế              | Mục đích                                              |
| --------------------------------------- | ------------------- | ----------------------------------------------------- |
| `DisableFormValueModelBindingAttribute` | MVC Resource Filter | Ngăn MVC tự đọc dữ liệu form để phục vụ model binding |
| `app.UseWhen(...)`                      | Middleware Pipeline | Chạy Transaction Middleware có điều kiện              |

# **Phần 1. DisableFormValueModelBindingAttribute**

## **1. Trước tiên cần hiểu Model Binding là gì?**

Giả sử bạn có một API upload file:

```
[HttpPost("upload")]
public async Task<IActionResult> Upload(
    IFormFile file)
{
    // Process file
    return Ok();
}
```

Client gửi HTTP request với `Content-Type: multipart/form-data`, chứa một file `video.mp4`.

ASP.NET Core có cơ chế gọi là **Model Binding** giúp bạn tự động lấy dữ liệu từ HTTP request và chuyển thành tham số của action.

Ví dụ:

```
public IActionResult CreateUser(
    [FromForm] CreateUserRequest request)
```

Giả sử client gửi:

```
POST /users
Content-Type: multipart/form-data

Name = John
Age = 25
Avatar = avatar.png
```

ASP.NET Core sẽ cố gắng lấy dữ liệu từ form, chuyển đổi giá trị tương ứng sang kiểu dữ liệu C# và gán vào object `CreateUserRequest`.

Bạn không cần tự đọc từng field trong `HttpContext.Request`.

**Vấn đề xảy ra khi upload file lớn.**

Khi MVC model binding đọc dữ liệu multipart form, framework có thể buffer nội dung file vào bộ nhớ hoặc file tạm trên ổ đĩa trước khi action bắt đầu xử lý.

Ví dụ bạn upload video 2 GB:

- Request gửi lên server.
- MVC đọc và xử lý form.
- File được buffer theo cơ chế của ASP.NET Core.
- Sau đó action mới bắt đầu làm việc với `IFormFile`.

Điều này không có nghĩa toàn bộ 2 GB luôn nằm trong RAM. ASP.NET Core có cơ chế chuyển sang lưu file tạm khi vượt ngưỡng buffer bộ nhớ.

Tuy nhiên, nếu bạn muốn **Streaming Upload**, bạn thường muốn tự đọc multipart request theo từng phần bằng `MultipartReader`, thay vì để MVC xử lý form trước.

Đó là lý do có attribute này.

## **2. Giải thích từng thành phần của class**

```
[AttributeUsage(AttributeTargets.Method)]
public sealed class DisableFormValueModelBindingAttribute
    : Attribute, IResourceFilter
```

### **A.&#x20;**`[AttributeUsage(AttributeTargets.Method)]`

Đây là một attribute dùng để quy định **attribute do bạn tạo được phép gắn vào đâu**.

Ví dụ:

```
[DisableFormValueModelBinding]
[HttpPost("upload-stream")]
public async Task<IActionResult> UploadStream()
{
    return Ok();
}
```

`AttributeTargets.Method` nghĩa là chỉ được áp dụng lên method.

Một số loại target khác:

| Target      | Ý nghĩa                     |
| ----------- | --------------------------- |
| `Method`    | Method                      |
| `Class`     | Class                       |
| `Property`  | Property                    |
| `Parameter` | Tham số                     |
| `All`       | Các loại target được hỗ trợ |

### **B.&#x20;**`public sealed class`

- `public`: Class có thể được sử dụng từ những nơi khác có quyền truy cập.
- `class`: Khai báo một class.
- `sealed`: Không cho phép class khác kế thừa class này.

Ví dụ:

```
public sealed class MyAttribute { }

// Compile error
public class OtherAttribute : MyAttribute { }
```

Ở đây dùng `sealed` vì attribute này chỉ có một trách nhiệm cụ thể, không cần thiết kế để kế thừa.

### **C.&#x20;**`: Attribute, IResourceFilter`

Đây là phần quan trọng nhất.

`Attribute`**&#x20;là gì?**

`System.Attribute` là base class dùng để định nghĩa custom attribute trong .NET.

Ví dụ:

```
[Obsolete]
public void OldMethod()
{
}
```

`Obsolete` cũng là một attribute.

Khi kế thừa `Attribute`, bạn có thể tạo một attribute riêng:

```
public class MyCustomAttribute : Attribute
{
}
```

`IResourceFilter`**&#x20;là gì?**

Đây là một interface của ASP.NET Core MVC, cung cấp hai method:

```
public interface IResourceFilter
{
    void OnResourceExecuting(ResourceExecutingContext context);

    void OnResourceExecuted(ResourceExecutedContext context);
}
```

Nó cho phép thực thi logic tại một giai đoạn cụ thể trong quá trình xử lý MVC request.

Luồng xử lý đơn giản hóa của MVC

HTTP Request

Middleware Pipeline

Routing / Endpoint Selection

Authorization

**Resource Filter — OnResourceExecuting**

Model Binding

Action / Controller

**Resource Filter — OnResourceExecuted**

HTTP Response

Minh họa luồng điển hình. Các filter khác, exception và short-circuit có thể làm thay đổi đường đi thực tế.

Điểm quan trọng: `OnResourceExecuting`**&#x20;chạy trước Model Binding**.

Điều này giúp bạn can thiệp vào quá trình MVC chuẩn bị đọc và bind form.

## **3. Giải thích OnResourceExecuting**

```
public void OnResourceExecuting(
    ResourceExecutingContext context)
{
    context.ValueProviderFactories
        .RemoveType<FormValueProviderFactory>();

    context.ValueProviderFactories
        .RemoveType<FormFileValueProviderFactory>();

    context.ValueProviderFactories
        .RemoveType<JQueryFormValueProviderFactory>();
}
```

Đầu tiên cần hiểu:

`ResourceExecutingContext` chứa thông tin và trạng thái liên quan đến request đang được MVC xử lý tại giai đoạn Resource Filter.

Trong đó:

```
context.ValueProviderFactories
```

là một collection chứa các factory mà MVC có thể dùng để tạo `ValueProvider`.

`ValueProvider` là thành phần giúp Model Binding tìm giá trị theo tên, ví dụ `Name`, `Age`, `Email`, từ các nguồn dữ liệu được hỗ trợ.

Ví dụ:

```
public IActionResult Create([FromForm] string name)
```

Model Binding cần tìm giá trị của `name` từ dữ liệu form.

### **Ba dòng RemoveType có tác dụng gì?**

**Dòng 1:**

```
.RemoveType<FormValueProviderFactory>();
```

Loại bỏ factory cung cấp các giá trị từ form fields.

Ví dụ:

```
Name = John
Age = 25
```

**Dòng 2:**

```
.RemoveType<FormFileValueProviderFactory>();
```

Loại bỏ factory cung cấp tên file trong form cho hệ thống value provider, chủ yếu phục vụ binding các tên/prefix liên quan đến file.

Lưu ý: Nó không phải thành phần trực tiếp tạo `IFormFile`. Việc bind `IFormFile` được thực hiện bởi binder riêng.

**Dòng 3:**

```
.RemoveType<JQueryFormValueProviderFactory>();
```

Loại bỏ factory hỗ trợ kiểu đặt tên field theo cú pháp form của jQuery.

Ví dụ:

```
users[0].name = John
users[1].name = Anna
```

Tóm lại, ba dòng này **loại bỏ các form value-provider factory khỏi danh sách dùng cho model binding của action hiện tại**.

Chúng không xóa dữ liệu request, không tắt toàn bộ model binding và cũng không tự động tắt mọi cơ chế đọc form khác.

## **4. OnResourceExecuted để làm gì?**

```
public void OnResourceExecuted(
    ResourceExecutedContext context)
{
}
```

Method này chạy khi phần xử lý tiếp theo của resource pipeline hoàn tất.

Bạn có thể sử dụng để thực hiện các công việc sau xử lý, ví dụ ghi log hoặc dọn dẹp tài nguyên khi phù hợp.

Trong trường hợp này, method để trống vì chúng ta chỉ cần can thiệp trước khi Model Binding hoạt động.

## **5. Áp dụng vào Streaming Upload**

```
[HttpPost("upload-stream")]
[DisableFormValueModelBinding]
public async Task<IActionResult> UploadStream(
    CancellationToken cancellationToken)
{
    var boundary = GetBoundary(Request.ContentType);

    var reader = new MultipartReader(
        boundary,
        Request.Body);

    MultipartSection? section;

    while ((section = await reader.ReadNextSectionAsync(
        cancellationToken)) != null)
    {
        // Kiểm tra headers để xác định file section
        // Đọc section.Body và copy đến nơi lưu trữ
    }

    return Ok();
}
```

Ở đây `GetBoundary` là hàm trợ giúp bạn cần tự triển khai để trích xuất và kiểm tra multipart boundary.

Nhờ attribute, các form value provider mặc định không còn được sử dụng để bind dữ liệu form cho action này. Bạn có thể chủ động đọc request body bằng `MultipartReader` và xử lý theo stream.

Cần lưu ý:

- Không đồng thời dùng `IFormFile` hoặc `[FromForm]` cho nội dung multipart mà bạn định tự đọc.
- Kiểm tra `Content-Type`, boundary, kích thước và số lượng section.
- Đảm bảo middleware, filter hoặc code khác chưa đọc hay tiêu thụ `Request.Body`.

**Một cách nhớ đơn giản:** Attribute này giống như nói với MVC: *“Đừng tự đọc form để bind dữ liệu cho action này. Tôi sẽ chủ động xử lý multipart request.”*

# **Phần 2. app.UseWhen và TransactionMiddleware**

Đây là đoạn code thứ hai:

```
app.UseWhen(
    context => context.GetEndpoint()?
        .Metadata.GetMetadata<SkipTransactionAttribute>() is null,
    branch => branch.UseMiddleware<TransactionMiddleware>());
```

Để hiểu nó, bạn cần nắm bốn khái niệm: Middleware, `UseWhen`, Endpoint Metadata và Attribute.

## **1. Middleware là gì?**

Middleware là một thành phần nằm trong HTTP request pipeline, có thể xử lý request trước khi đến Controller và response sau khi Controller xử lý.

Ví dụ:

```
public class LoggingMiddleware
{
    private readonly RequestDelegate _next;

    public LoggingMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        Console.WriteLine("Before Controller");

        await _next(context);

        Console.WriteLine("After Controller");
    }
}
```

Khi gọi:

```
app.UseMiddleware<LoggingMiddleware>();
```

Request sẽ đi qua middleware.

```
HTTP Request
    |
    v
LoggingMiddleware
    |
    | Before Controller
    |
    v
Controller
    |
    v
LoggingMiddleware
    |
    | After Controller
    |
    v
HTTP Response
```

`await _next(context)` có nghĩa là chuyển request sang thành phần tiếp theo trong pipeline.

Nếu middleware không gọi `_next`, nó có thể kết thúc request ngay tại đó.

## **2.&#x20;**`UseWhen`**&#x20;là gì?**

`UseWhen` cho phép bạn chạy một nhánh middleware **khi một điều kiện được thỏa mãn**.

Ví dụ đơn giản:

```
app.UseWhen(
    context => context.Request.Path.StartsWithSegments("/admin"),
    branch => branch.UseMiddleware<LoggingMiddleware>());
```

Giải thích:

- Nếu request bắt đầu bằng `/admin`, chạy `LoggingMiddleware`.
- Nếu request không bắt đầu bằng `/admin`, bỏ qua `LoggingMiddleware`.
- Sau khi nhánh hoàn thành bình thường, request tiếp tục qua main pipeline.

Cách UseWhen hoạt động

Hai nhánh cùng tiếp tục vào pipeline chính, miễn là nhánh middleware không kết thúc request sớm.

## **3. Giải thích&#x20;**`GetEndpoint()`

```
context.GetEndpoint()
```

`context` ở đây là `HttpContext`, chứa thông tin của HTTP request hiện tại.

`GetEndpoint()` lấy endpoint đã được routing chọn cho request.

Ví dụ bạn có controller:

```
[ApiController]
[Route("api/users")]
public class UsersController : ControllerBase
{
    [HttpGet]
    public IActionResult GetUsers()
    {
        return Ok();
    }

    [HttpPost]
    public IActionResult CreateUser()
    {
        return Ok();
    }
}
```

Khi client gọi:

```
GET /api/users
```

Routing sẽ chọn endpoint tương ứng với `GetUsers()`.

Từ `HttpContext`, bạn có thể truy cập endpoint đã chọn:

```
var endpoint = context.GetEndpoint();
```

**Lưu ý:** `GetEndpoint()` có thể trả về `null` nếu routing chưa được thực hiện hoặc không tìm thấy endpoint phù hợp.

## **4. Endpoint Metadata là gì?**

Bạn có thể hiểu Metadata là những thông tin bổ sung mô tả một endpoint.

Ví dụ:

```
[HttpPost("upload")]
[Authorize]
[DisableFormValueModelBinding]
public IActionResult Upload()
{
    return Ok();
}
```

Các attribute có thể cung cấp metadata cho endpoint hoặc tham gia vào cơ chế filter của MVC, tùy loại attribute.

ASP.NET Core cho phép đọc endpoint metadata như sau:

```
var endpoint = context.GetEndpoint();

var metadata = endpoint?.Metadata;
```

Đây là cơ chế rất hữu ích khi bạn muốn middleware thay đổi hành vi theo từng API.

## **5.&#x20;**`SkipTransactionAttribute`**&#x20;là gì?**

Đây thường là một custom attribute do developer tự định nghĩa.

Ví dụ:

```
[AttributeUsage(
    AttributeTargets.Method | AttributeTargets.Class)]
public sealed class SkipTransactionAttribute : Attribute
{
}
```

Class này không có method hay property nào.

Vậy nó làm gì?

Nó đóng vai trò **marker attribute**, tức là một dấu đánh dấu để những thành phần khác nhận biết.

Ví dụ:

```
[HttpGet("users")]
[SkipTransaction]
public IActionResult GetUsers()
{
    return Ok();
}
```

Bạn đang đánh dấu rằng endpoint này không cần Transaction Middleware.

Bản thân attribute không tự skip transaction. Middleware hoặc cấu hình pipeline phải đọc marker đó và thực hiện hành vi tương ứng.

## **6.&#x20;**`GetMetadata<SkipTransactionAttribute>()`**&#x20;nghĩa là gì?**

```
context.GetEndpoint()?
    .Metadata.GetMetadata<SkipTransactionAttribute>()
```

Hãy tách ra:

```
var endpoint = context.GetEndpoint();
```

Lấy endpoint hiện tại.

```
var skipAttribute =
    endpoint?.Metadata.GetMetadata<SkipTransactionAttribute>();
```

Tìm xem endpoint có metadata thuộc kiểu `SkipTransactionAttribute` hay không.

Nếu có, trả về đối tượng attribute tương ứng. Nếu không có, trả về `null`.

Ở đây có cú pháp quan trọng của C#:

```
?. 
```

Đây là **null-conditional operator**.

Nó giúp tránh lỗi `NullReferenceException` khi endpoint là `null`.

Tiếp theo:

```
is null
```

Kiểm tra kết quả có bằng `null` hay không.

Vì vậy:

```
context.GetEndpoint()?
    .Metadata.GetMetadata<SkipTransactionAttribute>() is null
```

có nghĩa là:

**Endpoint không có&#x20;**`SkipTransactionAttribute`**, hoặc không tìm thấy endpoint, thì điều kiện trả về&#x20;**`true`**.**

## **7. Phân tích toàn bộ UseWhen**

```
app.UseWhen(
    context => context.GetEndpoint()?
        .Metadata.GetMetadata<SkipTransactionAttribute>() is null,
    branch => branch.UseMiddleware<TransactionMiddleware>());
```

Ta có thể viết lại thành dạng dài hơn để Fresher dễ hiểu:

```
app.UseWhen(
    context =>
    {
        var endpoint = context.GetEndpoint();

        var skipTransaction = endpoint?
            .Metadata.GetMetadata<SkipTransactionAttribute>();

        return skipTransaction == null;
    },
    branch =>
    {
        branch.UseMiddleware<TransactionMiddleware>();
    });
```

Giả sử có ba API:

```
[HttpGet("users")]
[SkipTransaction]
public IActionResult GetUsers()
{
    return Ok();
}

[HttpPost("users")]
public IActionResult CreateUser()
{
    return Ok();
}

[HttpPut("users/{id}")]
public IActionResult UpdateUser(int id)
{
    return Ok();
}
```

Kết quả:

| API          | Có SkipTransaction? | TransactionMiddleware |
| ------------ | ------------------- | --------------------- |
| GET /users   | Có                  | Bỏ qua                |
| POST /users  | Không               | Chạy                  |
| PUT /users/1 | Không               | Chạy                  |

Còn với request không có endpoint được chọn, điều kiện trong code gốc vẫn là `true`, nên Transaction Middleware vẫn chạy nếu request đi đến vị trí đó trong pipeline.

## **8. TransactionMiddleware thực tế có thể làm gì?**

Ví dụ đơn giản:

```
public class TransactionMiddleware
{
    private readonly RequestDelegate _next;

    public TransactionMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(
        HttpContext context,
        AppDbContext dbContext)
    {
        await using var transaction =
            await dbContext.Database.BeginTransactionAsync();

        try
        {
            await _next(context);

            await transaction.CommitAsync();
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

Giải thích:

- `BeginTransactionAsync()`: Bắt đầu database transaction.
- `_next(context)`: Cho request đi tiếp đến Controller và các thành phần còn lại.
- `CommitAsync()`: Xác nhận những thay đổi của transaction.
- `RollbackAsync()`: Hủy những thay đổi chưa được commit nếu có exception.

Ví dụ Controller thực hiện:

```
[HttpPost("transfer")]
public async Task<IActionResult> Transfer()
{
    // Trừ tiền tài khoản A
    // Cộng tiền tài khoản B
    // SaveChangesAsync()

    return Ok();
}
```

Nếu trong cùng database transaction, bước trừ tiền thành công nhưng bước cộng tiền bị exception, middleware có thể rollback để không lưu trạng thái dở dang.

Tuy nhiên, đây chỉ là ví dụ để học, chưa phải thiết kế Transaction Middleware hoàn chỉnh cho production.

Có ba điểm bạn cần lưu ý:

1. **HTTP 400/500 không tự động gây rollback.** Nếu downstream trả về lỗi mà không throw exception, ví dụ `return BadRequest()`, code trên vẫn có thể commit.
2. Transaction có thể bị giữ mở trong suốt thời gian request thực thi, kể cả khi đang upload file lớn hoặc gọi external API. Điều này có thể gây tốn tài nguyên và kéo dài thời gian giữ khóa database.
3. Database transaction không tự rollback các thao tác bên ngoài database như ghi file lên S3, gửi email hay gọi API bên thứ ba.

Đặc biệt với hệ thống upload file bạn đang học, mình không khuyến nghị tự động mở database transaction cho toàn bộ thời gian streaming file.

## **9. Một điểm rất quan trọng: thứ tự middleware**

Vì code của bạn cần:

```
context.GetEndpoint()
```

nên routing phải hoàn tất việc lựa chọn endpoint trước khi điều kiện này được kiểm tra.

Cách khai báo rõ ràng:

```
app.UseRouting();

app.UseWhen(
    context => context.GetEndpoint()?
        .Metadata.GetMetadata<SkipTransactionAttribute>() is null,
    branch => branch.UseMiddleware<TransactionMiddleware>());

app.MapControllers();
```

Trong mô hình `WebApplication`, ASP.NET Core có thể tự thêm routing middleware, nhưng khi logic phụ thuộc trực tiếp vào endpoint metadata thì việc đặt `UseRouting()` rõ ràng giúp bạn dễ kiểm soát thứ tự hơn.

Nếu đặt `UseWhen` trước khi routing chọn endpoint, `GetEndpoint()` có thể là `null`, khiến `TransactionMiddleware` chạy kể cả với API có `[SkipTransaction]`.&#x20;

# **Phần 3. Kết hợp hai đoạn code trong API Upload**

Giả sử bạn xây dựng API upload file lớn và có `TransactionMiddleware` toàn cục.

Bạn có thể viết:

```
[HttpPost("upload-stream")]
[DisableFormValueModelBinding]
[SkipTransaction]
public async Task<IActionResult> UploadStream()
{
    // Streaming file đến local storage
    return Ok();
}
```

Khi client gọi API, request sẽ đi qua các bước:

1\. HTTP Request

Client gửi multipart/form-data

2\. Routing

Tìm endpoint UploadStream

## **Tổng kết để ghi nhớ**

| Thành phần                 | Hiểu đơn giản                                             |
| -------------------------- | --------------------------------------------------------- |
| `Attribute`                | Thêm thông tin hoặc đánh dấu cho class, method...         |
| `AttributeUsage`           | Quy định attribute được sử dụng ở đâu                     |
| `IResourceFilter`          | Can thiệp vào MVC trước/sau phần xử lý resource tiếp theo |
| `ValueProviderFactory`     | Tạo thành phần cung cấp dữ liệu cho model binding         |
| `RemoveType<T>()`          | Loại bỏ phần tử có kiểu `T` khỏi collection tương ứng     |
| `Middleware`               | Xử lý HTTP request/response trong pipeline                |
| `UseWhen`                  | Chạy nhánh middleware nếu điều kiện đúng                  |
| `GetEndpoint()`            | Lấy endpoint đã được routing chọn                         |
| `Metadata`                 | Thông tin bổ sung gắn với endpoint                        |
| `GetMetadata<T>()`         | Tìm metadata thuộc kiểu `T`                               |
| `is null`                  | Kiểm tra giá trị có phải `null`                           |
| `SkipTransactionAttribute` | Marker để middleware quyết định bỏ qua transaction        |

**Điểm cốt lõi:** Đoạn code đầu điều khiển cách MVC xử lý dữ liệu form trước Controller. Đoạn code thứ hai điều khiển việc một Middleware có được chạy hay không dựa trên metadata của endpoint.

Hiểu được hai đoạn này nghĩa là bạn đã nắm được một phần quan trọng về cách ASP.NET Core cho phép developer tùy chỉnh HTTP request pipeline.
